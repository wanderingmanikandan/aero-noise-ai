Use real airfoil measurements to make a noise prediction. Then check it against an experiment the model did not train on.

Five steps. One simple model. Evidence you can explain.

The aerospace problem

Air flowing over an airfoil can generate noise.

We study existing wind-tunnel measurements from NACA 0012 airfoils. An airfoil is the cross-sectional shape of a wing-like surface.

The research question

Can a small model beat a simple baseline?

We compare five-neighbour regression with always predicting the average training noise level. Both are tested on exactly the same held-out rows.

Your role

Run, check, and explain.

You do not need to write code during the pitch. You do need to understand the inputs, the prediction method, the test, and the limits.

Know the boundary. We predict the dataset’s scaled sound pressure level, in dB, at an input frequency. This is not total aircraft noise, a flight test, a safety decision, or an aircraft design tool.
Six words to learn before you start

Input: a measurement supplied to the model, such as airflow speed.

Target: the measured value we want to predict: scaled sound pressure level.

Training set: the examples available to the model for learning.

Test set: separate examples used to check the model.

Baseline: a simple method the model should be compared with.

Prediction error: the difference between a prediction and its measured value.

Why keep some rows together in the test?

Several rows share the same angle, chord, speed, and displacement thickness but have different frequencies. We define these as a condition group. The app finds 106 such groups and keeps each group entirely in training or testing.

This reduces one obvious source of overly similar train/test examples. These are constructed groups, not supplied experimental run IDs. It is still a limited benchmark, not a guarantee of independent real-world performance.

Say it in your own words

“We use five experimental inputs to predict a measured noise value. We reserve complete condition groups for testing so the model does not train on those same rows.”

Teacher / research details: exactly what was calculated?

No neural network, language model, API, or confidence estimator is used. The model stores training examples and performs nearest-neighbour regression. Predictions use the raw five inputs after z-score standardisation, fitted only on training rows. Distances are Euclidean; neighbour targets are averaged uniformly.

This is one fixed split per experiment, with no hyperparameter search. Do not choose or modify settings based on these final test results and then report the same test as untouched.

Keep the claim modest

Airfoil-noise prediction and nearest-neighbour methods already exist. This project’s scope is a student research understanding and a reproducible browser demonstration, not a claim of a new algorithm or a certified aerospace product.

Neither a low error nor a good single-case prediction proves causal relationships, safety, flight readiness, or performance on another airfoil.

Five questions the aerospace faculty may ask

Is this real data?
Yes. Public NASA airfoil measurements distributed by UCI. We did not conduct these wind-tunnel experiments.

Where is the AI?
In supervised nearest-neighbour regression: numerical predictions are made from similar labelled training observations.

Why not use a neural network?
This project prioritises a transparent, lightweight baseline experiment that beginners can understand and reproduce.

What is new?
We propose an accessible browser demonstration and a defined evaluation question. We do not claim the prediction topic or algorithm is new.

Can it design a quiet aircraft?
No. It estimates a dataset-specific scaled noise value. Design changes require new experiments, appropriate physics, and validation.

Team self-check: three short questions

1. Which rows are used to calculate input means and standard deviations?

2. What does an MAE of 3 dB mean in this app?

3. What does a held-out case show?

How do we share this app on GitHub Pages?

Download and extract the provided repository ZIP. Create a public GitHub repository, then upload the extracted files and folders so index.html is at its top level. Do not upload only the ZIP.

Open Settings → Pages → Deploy from a branch → main → /(root) → Save. GitHub will display the site address after deployment. Share that website address, not the source-code page.

Public repositories and their Pages content are visible online. Do not publish students’ personal details or private files. This app works from any repository name; it has no hard-coded account or path.
